The right order

Company first. Contact second. Deal third.

操作順序與真實 CRM 使用者一致

02
1

Create company 建立公司

Industry options come from a fixed set of values — the field can only hold valid values. No free-text surprises.

2

Create contact 建立聯絡人

Email is the unique key. Duplicates are rejected and the UI maps the error back to the exact field.

3

Create deal 建立交易

Pipeline selection loads its stages live. Pick the wrong stage for a pipeline and the app says no.

4

Associate and cross-link 建立關聯與跨模組連結

Link the deal to a contact or company from the row action menu. The Defects module can point at a company the same way.

Master data first 先建立主檔資料

Company and contact records are created before any deal association is attempted.在嘗試建立交易關聯之前，先建立公司與聯絡人紀錄。

Deal second 交易次之

Pipeline and stage metadata are built in, so the deal form follows real CRM rules.流程與階段中繼資料為內建，交易表單依循真實 CRM 規則。

Relationships last 關聯最後建立

The user links records from row actions instead of manually typing IDs or guessing association targets.使用者透過列操作建立關聯，無需手動輸入 ID 或猜測關聯對象。

Design principle: 設計原則：UI enforces the CRM object hierarchy — master data before relationships. 介面強制遵循 CRM 物件階層——先主檔資料，後關聯。

Linking records

Connect a deal to the right person and company

04

Associate modal — opened from the ⋯ row menu. Writes a link into the store. After saving, the ▶ row toggle shows the new link immediately.
關聯彈窗 — 從 ⋯ 選單開啟，將連結寫入資料儲存中。儲存後，▶ 展開列即可立即驗證新的關聯。

Why this detail matters 為何這個細節很重要

Most CRM integrations get this wrong first time. Association records are their own entity — bidirectional links, not a field on the deal. The app makes that explicit.
大多數 CRM 整合第一次都會做錯這點。關聯紀錄是獨立的實體——雙向連結，而非交易上的欄位。本應用程式將此明確呈現。

⋯

One click from any table row 任意列一鍵發起關聯

Open the action menu, choose Associate… — modal opens with the right context already set.

▶

Inline links — click ▶ to expand 點擊 ▶ 展開關聯紀錄

Every row in Deals, Contacts, and Companies has a ▶ toggle. Click it to see linked records inline — no separate screen needed. Only one row can be open at a time.

Design detail: 設計細節：every association is written both ways at once — deal→contact and contact→deal — so either side can query it directly 每筆關聯會同時寫入雙向——交易→聯絡人與聯絡人→交易——任一方都能直接查詢。

API

One parser 統一錯誤解析器

The API wrapper extracts messages and field errors from every response, in one place.

UI

One renderer 統一錯誤渲染器

The shared UI helper adds summary blocks, invalid styles, and inline hints.

MOD

Appendix

The app's own API surface

應用程式自己的 API 介面

REF

CRUD objects CRUD 物件操作

List, create, update, and delete records for deals, contacts, companies, and defects — same shape for every module.列出、建立、更新、刪除交易、聯絡人、公司與瑕疵記錄——每個模組結構一致。

GET /api/{type} POST /api/{type} PATCH /api/{type}/{id} DELETE /api/{type}/{id}

Search and filters 搜尋與篩選

Deal search powers name, stage, and pipeline filtering against the in-memory store.交易搜尋支援依名稱、階段與流程對記憶體中的資料進行篩選。

POST /api/deals/search

Metadata 中繼資料

Form dropdowns read from built-in metadata, so the user cannot submit invalid options.表單下拉選單讀取內建中繼資料，使用者無法送出無效選項。

GET /api/pipelines GET /api/bootstrap

Associations 關聯

Links are written both directions at once and stored alongside the records — no fixed type-id table to memorize.連結會同時寫入雙向並與紀錄一起儲存——不需要記住固定的 type-id 對照表。

GET /api/associations/{dealId}/{type} POST /api/associate

One association store, shared by deals, contacts, and companies.單一關聯儲存區，交易、聯絡人與公司共用。

Data: 資料：Everything persists to App_Data/crm-store.json. No auth header, no external base URL — it's all local. 所有資料都持久化到 App_Data/crm-store.json。沒有驗證標頭，沒有外部 Base URL——完全在本機。
